  169: =head1 DESCRIPTION
  170: 
  171: C<HTML::OSM> builds an interactive map from OpenStreetMap tiles and the
  172: Leaflet.js library.  Give it points as latitude and longitude, as place
  173: names, or as geocoder result objects.  It can also draw GeoJSON shapes,
  174: heatmaps, GPX tracks and choropleth (colour-filled region) layers, and can
  175: group nearby markers into clusters.  A named GeoJSON layer gets a checkbox on
  176: the map, so the reader can turn it on and off.
  177: 
  178: Place names are turned into coordinates by an injected geocoder or, without
  179: one, by the Nominatim service.  The answers are cached, and requests can be
  180: spaced out with C<min_interval>.
  181: 
  182: C<onload_render()> returns two HTML fragments: one for the page's
  183: C<< <head> >> and one for its C<< <body> >>.  The interface follows
  184: L<HTML::GoogleMaps::V3>, so code written for that module needs few changes.
  185:

  201: C<< scale => 1 >> adds Leaflet's scale bar, in kilometres and miles, to the
  202: bottom left corner.  It is redrawn whenever the map moves or zooms.  The
  203: default is no scale bar.
  204: 
  205: C<legend> draws a key in a corner of the map: C<legend_position> is
  206: C<topright> (the default), C<topleft>, C<bottomright> or C<bottomleft>.
  207: C<legend_title> is printed above the entries.  Each entry is a hashref:
  208: 
  209: =over 4
  210: 
  211: =item C<label>
  212: 
  213: The text, required.  It is written as text, never as HTML.
  214: 
  215: =item C<colour>
  216: 
  217: A hex colour, C<#rgb> or C<#rrggbb>, for the round swatch.  The default is
  218: C<#3388ff>, Leaflet's own blue.
  219: 
  220: =item C<radius>
  221: 
  222: The swatch's radius in pixels, for a key to the sizes of circle markers.
  223: Without it the swatch is 12 pixels across.  A large radius is drawn at
  224: most 50 pixels across.
  225: 
  226: =item C<group>
  227: 
  228: The entry is listed only while a marker given the same C<group> (through
  229: C<add_marker> or C<add_circle_marker>) is inside the map's view.  Each time
  230: the reader pans or zooms, the key is drawn again, so it shows only the
  231: entries for what can be seen.  A marker hidden in a cluster still counts.
  232: An entry without a group is always listed.
  233: 
  234: =back
  235: 
  236: When no entry is listed, the key says C<legend_empty>, by default
  237: "Nothing in this view".
  238: 
  239: C<new()> croaks on an entry it cannot use, and on an unknown position.
  240: Values from a config file or a clone skip that check, so C<onload_render()>
  241: checks them again.  It leaves out a bad entry and uses C<topright> for a bad
  242: position, with a warning.

 2019: =head1 LIMITATIONS
 2020: 
 2021: =over 4
 2022: 
 2023: =item * B<Per-marker removal>: Markers added via C<add_marker()> cannot yet be
 2024: removed individually by clicking them.  The "Clear search markers" button only
 2025: removes markers added by the in-page Nominatim search box.
 2026: 
 2027: =item * B<Clone validation>: The clone path (C<< $obj->new(%overrides) >>)
 2028: bypasses the Params::Validate::Strict schema so subclasses and internal callers
 2029: can merge arbitrary state.  Callers are responsible for passing valid overrides.
 2030: 
 2031: =item * B<Config-file params unvalidated>: Keys injected by
 2032: L<Object::Configure> from a config file are not re-run through the schema, so
 2033: a malformed config file can introduce invalid types at runtime.
 2034: C<onload_render()> checks C<zoom>, C<max_zoom>, C<width> and C<height> again and
 2035: HTML-escapes the CDN URLs, so a bad value cannot inject markup into the page.
 2036: 
 2037: =item * B<One map per page>: The rendered HTML uses fixed element IDs
 2038: (C<map>, C<search-box>, C<clear-search-button> and C<reset-button>), so two
 2039: maps on the same page will clash.
 2040: 
 2041: =item * B<Clustered circle markers>: With C<< cluster => 1 >>, circle markers
 2042: are grouped with the pin markers, so at low zoom levels a cluster count is
 2043: shown in place of the circles' sizes.  Leave C<cluster> off for a bubble map
 2044: whose sizes should always be visible.
 2045: 
 2046: =item * B<Private-method encapsulation>: C<_fetch_coordinates>, C<_validate>,
 2047: and C<_js_string> are named with a leading underscore by convention only.
 2048: Using L<Sub::Private> in C<enforce> mode would make the contract explicit, but
 2049: that module is not yet listed as a dependency to avoid breaking white-box tests
 2050: in C<t/mock.t>.
 2051: 
 2052: =item * B<Routing>: Turn-by-turn routing (Leaflet Routing Machine / OSRM) is
 2053: explicitly out of scope for this module and will not be added here.
