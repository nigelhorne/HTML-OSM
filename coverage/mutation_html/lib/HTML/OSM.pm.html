  172: =head1 DESCRIPTION
  173: 
  174: C<HTML::OSM> builds an interactive map from OpenStreetMap tiles and the
  175: Leaflet.js library.  Give it points as latitude and longitude, as place
  176: names, or as geocoder result objects.  It can also draw GeoJSON shapes,
  177: heatmaps, GPX tracks and choropleth (colour-filled region) layers, and can
  178: group nearby markers into clusters.  A named GeoJSON layer gets a checkbox on
  179: the map, so the reader can turn it on and off.
  180: 
  181: Place names are turned into coordinates by an injected geocoder or, without
  182: one, by the Nominatim service.  The answers are cached, and requests can be
  183: spaced out with C<min_interval>.
  184: 
  185: C<onload_render()> returns two HTML fragments: one for the page's
  186: C<< <head> >> and one for its C<< <body> >>.  The interface follows
  187: L<HTML::GoogleMaps::V3>, so code written for that module needs few changes.
  188:

  204: C<< scale => 1 >> adds Leaflet's scale bar, in kilometres and miles, to the
  205: bottom left corner.  It is redrawn whenever the map moves or zooms.  The
  206: default is no scale bar.
  207: 
  208: C<legend> draws a key in a corner of the map: C<legend_position> is
  209: C<topright> (the default), C<topleft>, C<bottomright> or C<bottomleft>.
  210: C<legend_title> is printed above the entries.  Each entry is a hashref:
  211: 
  212: =over 4
  213: 
  214: =item C<label>
  215: 
  216: The text, required.  It is written as text, never as HTML.
  217: 
  218: =item C<colour>
  219: 
  220: A hex colour, C<#rgb> or C<#rrggbb>, for the round swatch.  The default is
  221: C<#3388ff>, Leaflet's own blue.
  222: 
  223: =item C<radius>
  224: 
  225: The swatch's radius in pixels, for a key to the sizes of circle markers.
  226: Without it the swatch is 12 pixels across.  A large radius is drawn at
  227: most 50 pixels across.
  228: 
  229: =item C<group>
  230: 
  231: The entry is listed only while a marker given the same C<group> (through
  232: C<add_marker> or C<add_circle_marker>) is inside the map's view.  Each time
  233: the reader pans or zooms, the key is drawn again, so it shows only the
  234: entries for what can be seen.  A marker hidden in a cluster still counts.
  235: An entry without a group is always listed.
  236: 
  237: =back
  238: 
  239: When no entry is listed, the key says C<legend_empty>, by default
  240: "Nothing in this view".
  241: 
  242: C<new()> croaks on an entry it cannot use, and on an unknown position.
  243: Values from a config file or a clone skip that check, so C<onload_render()>
  244: checks them again.  It leaves out a bad entry and uses C<topright> for a bad
  245: position, with a warning.

 2152: =head1 LIMITATIONS
 2153: 
 2154: =over 4
 2155: 
 2156: =item * B<Per-marker removal>: Markers added via C<add_marker()> cannot yet be
 2157: removed individually by clicking them.  The "Clear search markers" button only
 2158: removes markers added by the in-page Nominatim search box.
 2159: 
 2160: =item * B<Clone validation>: The clone path (C<< $obj->new(%overrides) >>)
 2161: bypasses the Params::Validate::Strict schema so subclasses and internal callers
 2162: can merge arbitrary state.  Callers are responsible for passing valid overrides.
 2163: 
 2164: =item * B<Config-file params unvalidated>: Keys injected by
 2165: L<Object::Configure> from a config file are not re-run through the schema, so
 2166: a malformed config file can introduce invalid types at runtime.
 2167: C<onload_render()> checks C<zoom>, C<max_zoom>, C<width> and C<height> again and
 2168: HTML-escapes the CDN URLs, so a bad value cannot inject markup into the page.
 2169: 
 2170: =item * B<One map per page>: The rendered HTML uses fixed element IDs
 2171: (C<map>, C<search-box>, C<clear-search-button> and C<reset-button>), so two
 2172: maps on the same page will clash.
 2173: 
 2174: =item * B<Clustered circle markers>: With C<< cluster => 1 >>, circle markers
 2175: are grouped with the pin markers, so at low zoom levels a cluster count is
 2176: shown in place of the circles' sizes.  Leave C<cluster> off for a bubble map
 2177: whose sizes should always be visible.
 2178: 
 2179: =item * B<Private-method encapsulation>: C<_fetch_coordinates>, C<_validate>,
 2180: and C<_js_string> are named with a leading underscore by convention only.
 2181: Using L<Sub::Private> in C<enforce> mode would make the contract explicit, but
 2182: that module is not yet listed as a dependency to avoid breaking white-box tests
 2183: in C<t/mock.t>.
 2184: 
 2185: =item * B<Routing>: Turn-by-turn routing (Leaflet Routing Machine / OSRM) is
 2186: explicitly out of scope for this module and will not be added here.
